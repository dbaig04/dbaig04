# Delivery comparison: RPC (ERPC SWQoS) vs Jito bundle

Generated by `npx tsx src/engine/delivery-compare.ts`. **Everything under "Estimates" is a model, not a measurement.** Landing rates for this bot were never measured: that needs the gated live A/B (`--live`), which sends real transactions and requires the user's explicit approval.

## Cost model (exact, from the code)

- Fees/tips come from `fees.ts` `chooseExecutionFees` with the default risk caps: priority ≤ 50,000, tip ≤ 50,000, priority + tip ≤ 10% of the expected profit before execution costs, base 5,000.
- **RPC** (`DELIVERY=rpc`, default): tip = 0. A landed success costs base + priority; **a landed failure also costs base + priority** (fees are charged on failure). Dropped/expired costs 0.
- **Jito** (`DELIVERY=jito`): the tip is a transfer inside the same tx (tip-first policy). A landed success costs base + priority + tip. **A bundle whose tx would fail does not land: cost 0** (the tip reverts with the tx in any case). Not landing costs 0.
- Expected net per attempt = P(land) · [(1 − P(fail|land)) · (gross − success cost) − P(fail|land) · failed cost].
- Size caveat (measured on the 4 saved reference-wallet arb txs): 1,079–1,178 bytes as legacy txs, System program already present; the in-tx tip adds the tip account + a transfer ix = 49 bytes → 1,128–1,227 of the 1,232-byte limit (5 bytes headroom on the largest). A route touching one more bin array would not fit; `JitoSender.prepare` then refuses (logged as a `risk` row) rather than sending. A v0 tx with a lookup table or a 2-tx bundle would remove this limit.

Reading (model only): with equal landing rates the services are close. Below ~1,000,000 lamports gross both pay the same total (the 10% share binds), and Jito saves the landed-failure fee, so it edges ahead. Above that the shared policy makes the Jito arm pay priority + tip (105,000) against RPC's 55,000, so RPC wins unless on-chain failures are frequent. Inside a bundle the priority fee is largely redundant; a tip-only Jito policy would remove that gap (a decision for the fee-policy owner). Landing rate dominates every scenario, and it is unmeasured.
